## 2. Reglas obligatorias para el agente

### 2.1. Reglas de redacción

El agente debe redactar en forma **impersonal**, evitando expresiones como:

- “yo propongo”
- “nosotros creemos”
- “en mi opinión”
- “hicimos”
- “queremos”

Debe usar fórmulas como:

- “se propone”
- “se plantea”
- “se identifica”
- “se desarrolla”
- “el proyecto busca”
- “la plataforma permite”
- “se considera viable”

El tono debe ser claro, de nivel medio, entendible para exposición estudiantil, pero sin perder formalidad técnica.

### 2.2. Reglas de precisión

El agente no debe inventar datos. Cuando falte evidencia, debe escribir:

> [Dato pendiente de validar]

o

> [Completar con evidencia de encuesta, entrevista, captura o fuente]

No se deben colocar cantidades de gimnasios, precios de mercado, estadísticas o porcentajes si no hay fuente o evidencia.

### 2.3. Reglas de evidencia

Cada afirmación importante debe respaldarse con al menos uno de estos elementos:

- Encuesta.
- Entrevista.
- Captura del prototipo.
- Captura de base de datos.
- Captura del repositorio.
- Referencia bibliográfica.
- Observación de campo.
- Comparación con herramientas existentes.
- Tabla de costos.
- Evidencia de avance técnico.

### 2.4. Reglas de originalidad

El agente debe evitar copiar texto literal de los lineamientos o de otras fuentes. Puede usar la estructura, pero debe redactar el contenido con palabras propias y adaptadas a GymHub.

No se deben usar logos, imágenes, fotografías, música, frases, marcas o diseños de terceros sin autorización o sin fuente. Si se usan imágenes, deben estar numeradas, tituladas y con fuente.

### 2.5. Reglas sobre IA

Si se utilizó inteligencia artificial para apoyar el documento, código, diseño, organización de ideas o revisión de estilo, el documento debe incluir una sección breve llamada:

## Declaración de uso de inteligencia artificial

Debe indicar:

- Herramienta utilizada.
- Propósito de uso.
- Qué partes fueron apoyadas.
- Qué partes fueron verificadas por el equipo.
- Que la responsabilidad final del contenido pertenece al equipo.

Ejemplo base:

> Para el desarrollo del proyecto GymHub se utilizó inteligencia artificial como herramienta de apoyo en la organización de ideas, revisión de redacción, mejora de estructura del documento y apoyo en la resolución de dudas técnicas. El contenido final fue revisado, adaptado y validado por las personas estudiantes responsables del proyecto. La inteligencia artificial no sustituyó la investigación, el criterio propio ni la toma de decisiones del equipo.

# 22. Especificaciones de citación APA 7 para GymHub

El agente debe aplicar APA 7 en citas dentro del texto y en referencias. No basta con poner enlaces al final: toda fuente usada debe aparecer citada dentro del contenido.

## 22.1. Diferencia entre cita y referencia

- **Cita:** aparece dentro del texto y muestra autor y año.
- **Referencia:** aparece al final y contiene los datos completos de la fuente.

Ejemplo:

```text
Supabase permite gestionar servicios de base de datos y autenticación para aplicaciones web (Supabase, 2026).
```

Referencia:

```text
Supabase. (2026). Supabase Docs. https://supabase.com/docs
```

## 22.2. Cita parentética

Se usa cuando el dato se coloca al final de una idea.

```text
El desarrollo de aplicaciones web requiere una estructura que conecte interfaz, lógica del sistema y almacenamiento de datos (Django Software Foundation, 2026).
```

## 22.3. Cita narrativa

Se usa cuando el autor forma parte de la oración.

```text
Django Software Foundation (2026) explica que Django permite desarrollar aplicaciones web mediante una estructura organizada de componentes.
```

## 22.4. Cita directa corta

Solo usar si es estrictamente necesario. Debe tener autor, año y página, párrafo o sección. Si no hay página, usar sección o párrafo cuando sea posible.

```text
Según Autor (2026), “texto citado de menos de 40 palabras” (p. 5).
```

## 22.5. Cita directa larga

Evitarla en GymHub. El documento debe priorizar paráfrasis y análisis propio. Si se usa una cita de más de 40 palabras, debe ir en bloque, sin comillas y con sangría. En LaTeX puede manejarse con `quote`:

```latex
\begin{quote}
Texto citado largo con más de cuarenta palabras. Debe conservar la referencia con autor, año y página o párrafo correspondiente.
\end{quote}
```

## 22.6. Cita indirecta o paráfrasis

Es la forma recomendada para GymHub. El agente debe leer la fuente, comprenderla y escribir con palabras propias.

```text
El uso de servicios en la nube facilita que pequeñas plataformas puedan iniciar sin comprar infraestructura física propia (Supabase, 2026).
```

## 22.7. Entrevistas y comunicaciones personales

Las entrevistas no publicadas con dueños de gimnasios, entrenadores o usuarios deben citarse en el texto como comunicación personal. No van en la lista de referencias si no son recuperables por el lector.

Ejemplo narrativo:

```text
J. Pérez (comunicación personal, 15 de junio de 2026) indicó que el control de pagos en su gimnasio se realiza mediante hojas de cálculo.
```

Ejemplo parentético:

```text
En una consulta exploratoria se identificó que algunos gimnasios aún registran pagos de forma manual (J. Pérez, comunicación personal, 15 de junio de 2026).
```

### Regla de privacidad

Si no se tiene permiso para usar el nombre, se debe anonimizar:

```text
Un administrador de gimnasio local (comunicación personal, 15 de junio de 2026) indicó que el control de pagos se realiza de manera manual.
```

# 28. Indicaciones para el agente si debe convertir este Markdown a LaTeX

Cuando el agente reciba este archivo `.md` y deba producir un `.tex`, debe seguir este proceso:

1. Extraer la estructura principal del documento.
2. Convertir `#` en `\section{}` solo cuando corresponda al cuerpo del documento.
3. Convertir `##` en `\subsection{}`.
4. Convertir `###` en `\subsubsection{}` solo si es necesario.
5. Evitar exceso de profundidad en títulos.
6. Convertir listas extensas en tablas cuando mejore la claridad.
7. Mover instrucciones internas del agente a comentarios LaTeX con `%` o eliminarlas del documento final.
8. Mantener en el documento final únicamente contenido presentable ante ExpoTÉCNICA.
9. Crear `referencias.bib` con todas las fuentes citadas.
10. Verificar que toda cita `\parencite{}` tenga entrada en `referencias.bib`.
11. Compilar con biber.
12. Revisar visualmente numeración, tablas, figuras y márgenes.

Ejemplo de conversión:

Markdown:

```md
## Segmentos de mercado
GymHub se dirige a gimnasios pequeños y medianos...
```

LaTeX:

```latex
\subsection{Segmentos de mercado}
GymHub se dirige a gimnasios pequeños y medianos...
```
